## 0. 검토 결과 요약

- 문서의 문제 14개는 코드로도 확인됨. 작은 오류 3개(14번)도 실제로 있음.
  - `vv2.1.6`: `deviceLine()` 이 입력값 앞에 `v` 를 또 붙임 (`js/app.js` deviceLine)
  - 상세가 Esc 로 안 닫힘 (Esc 처리는 CS 담당 관리 창에만 있음)
  - 날짜 없이 쓴 처리 이력은 `splitTimeline()` 이 시각 칸을 빈칸으로 돌려줌
- 제안 방향(첫 화면 = 안 끝난 CS 전체, 월 집계는 리포트로)에 동의. 데이터가 한 달 십여 건이라 **전체 CS 를 한 번에 불러와 화면에서 거르는 방식**이 가장 단순함. 지금도 전체 기간 검색이 이미 그렇게 동작함(`ensureHistory`).
- 1차는 DB · Edge Function 변경 없이 화면만 바꿈. 3차 「상태 체계 정리」만 DB 제약(`status` 의 `delayed`) · AI 프롬프트 · 이전 기록에 영향이 있음.

## 1. 공통 원칙 (모든 차수)

- 기존 기능 53개(문서 부록 대조표)를 빠짐없이 옮김. 차수마다 대조표로 점검.
- 새 문구는 모두 한국어·영어 사전(`js/i18n.js`)에 넣음. 키 누락은 기존 테스트가 잡음.
- 정렬 · 보기 · 지연 판단 · 어긋남 판단 같은 규칙은 `js/lib.js` 순수 함수로 만들고 테스트를 먼저 씀.
- 목 하네스로 화면을 확인한 뒤, 차수마다 **한국어·영문 사용 가이드를 다시 캡처**(구조가 크게 바뀌므로 거의 전면 재작성).
- 차수마다 따로 배포. 1차만으로도 가장 큰 문제(월이 바뀌면 할 일이 사라짐)가 풀림.

## 5. 결정이 필요한 것

1. **1차의 위쪽 집계 칸.** 1차는 목록을 「미해결 전체」로 바꾸지만 위쪽 집계(도넛 · 미해결 · 심각도 · 티켓 연결)는 2차에서 바뀜. 그 사이 목록과 숫자가 어긋나는 문제(문서 1번)가 더 커짐.
   - 제안: 1차에서 집계 칸이 **지금 보이는 목록 기준**으로 세도록만 바꿈(+0.3 M/D). 카드 모양은 2차에서.
2. **「7일 넘게 열림 = 지연」 기준.** 경과일 7일 자동 강조와 DB 상태 「지연」이 같은 단어를 씀. 1차는 목업처럼 둘 다 보이게 두고, 정리는 3차 5번에서.
3. **사이드바(월간 요약 · 막대).** 3차 탭 분리 전까지는 지금 자리(왼쪽)에 그대로 둠. 다만 기준은 「보고 있는 달」 그대로라 1차 이후 목록(전체 미해결)과 기준이 다름 → 사이드바 머리에 「2026-11 기준」을 분명히 표시.
4. 기한 · 착수일 (문서 「〔기한 확인〕」).
5. 어긋난 3건(10-19 ×2, 10-20)의 CS 상태 정리는 CS 담당이 먼저 처리 (코드 작업 아님).
