# CS 콘솔 영문 버전 설계 — 화면 영어화 · CS 기록 번역 · 영문 가이드

작성일: 2026-11-04

## 왜

해외팀이 CS 현황을 참고용으로 본다. 지금은 화면 글자와 CS 기록(제목·현상 설명·처리 이력 등)이 모두 한국어라 읽을 수 없다. 같은 사이트에서 브라우저 언어에 따라 영어로 보이고, 사람이 쓴 CS 내용도 영어로 읽혀야 한다.

## 목표

1. **같은 사이트, 언어 자동 선택 + 직접 변경**: 처음에는 크롬(브라우저) 언어 설정을 따른다. 한국어면 지금 화면 그대로, 그 외는 영어 화면. 상단 오른쪽(로그아웃 옆) 「한국어 / English」 버튼으로 직접 바꿀 수 있다 (사용자 결정).
2. **화면 글자 영어화**: 버튼·메뉴·안내·오류 문구, 상태·심각도·기기 이름, 날짜 표기까지 영어로.
3. **CS 기록 번역**: 사람이 쓴 글을 Claude 로 번역해 **따로 저장**해 두고, 화면 언어에 맞는 쪽을 보여 준다. 한국어로 쓴 글은 영어 화면에서 영어로, 영어로 쓴 글은 한국어 화면에서 한국어로.
4. **월간 요약도 두 언어**로.
5. **영문 가이드**: 지금 한국어 가이드와 같은 구성으로, 영어 화면을 **영어 예시 데이터**로 캡처해 만든다.

## 하지 않는 것 (non-goals)

- 고객사 이름, 티켓 번호, 사람 이름(접수자·CS 담당·티켓 담당), 버전 번호 번역
- YouTrack·Jira 에서 읽어 오는 티켓 제목·상태 번역 (트래커 값 그대로 표시)
- 번역문을 사람이 직접 고치는 기능
- 한국어·영어 외 언어

## 실패로 치는 것 (anti-goals)

- 번역이 **원문을 덮어쓰는** 것. 원문은 `cs_tickets` 에 쓴 그대로 남아야 한다.
- 번역 저장이 `cs_tickets.updated_at` 을 바꿔 **열려 있는 수정 창이 충돌 오류**를 받는 것 (지금 낙관적 잠금이 `updated_at` 기준).
- 한국어 화면이 지금과 달라지는 것 (영어화 작업 중 한국어 문구·배치가 바뀌면 안 됨).
- 번역을 기다리느라 목록·상세가 늦게 뜨는 것.
- 고객사 이름·티켓 번호가 번역돼서 검색·필터가 어긋나는 것.

## 결정 사항

| 항목 | 결정 | 누가 |
|---|---|---|
| 형태 | 같은 사이트에 언어 설정 | 사용자 |
| 언어 선택 | 기본은 브라우저 언어(`navigator.languages`) 첫 항목이 `ko` 로 시작하면 한국어, 아니면 영어 | 사용자(크롬 따름) · 판정 규칙은 내 결정 |
| 언어 변경 버튼 | 상단 오른쪽 로그아웃 옆 「한국어 / English」. 누르면 그 브라우저에 기억(`localStorage`, 실패해도 동작)하고 새로고침 없이 화면을 다시 그린다. 기억된 값이 크롬 설정보다 우선 | 사용자(버튼) · 배치·기억 방식은 내 결정 |
| 로그인 화면 | 같은 규칙으로 언어 결정, 같은 버튼을 로그인 카드 아래에도 | 내 결정 |
| CS 기록 | Claude 로 번역해 별도 저장, 언어별로 표시 | 사용자 |
| 번역 엔진 | 기존 Edge Function `ai` 에 번역 모드 추가, 모델은 기존 `MODEL` | 내 결정 |
| 번역 저장 위치 | 새 테이블 `cs_ticket_translations` (아래). `cs_tickets` 에 컬럼을 두지 않음 | 내 결정. 같은 행에 쓰면 감사 트리거가 `updated_at` 을 바꿔 anti-goal 위반 |
| 수정 창에 보이는 값 | 항상 **원문** (저장되는 값이 원문이므로) | 내 결정 |
| 화면에 번역 표시 | 번역된 칸 옆에 작게 "번역됨/Translated", 상세에서 "원문 보기/Show original" 로 원문 확인 | 내 결정 |

## 번역할 칸 / 안 할 칸

| 번역함 | 그대로 |
|---|---|
| `title`, `description`, `notes`, `status_note`, `timeline[]` 각 항목 | `customer`, `reporter`, `assignee`, `ticket_assignee`, `version`, `tickets[]`, `device`(값), `status`·`severity`(키) |

- `device`·`status`·`severity` 는 저장된 키를 화면 언어 사전으로 바꿔 보여 준다 (예: `웹`→Web, `기타`→Other, `open`→In progress, `hotfix`→Hotfix). DB 값·check 제약은 바꾸지 않는다.
- 처리 이력 항목 앞의 날짜(`11/04 14:20`)는 번역 대상이 아니다. 지금처럼 `splitTimeline` 으로 날짜를 떼고 나머지 글만 번역한다.
- 번역 프롬프트에 "고객사 이름·티켓 ID·사람 이름·제품명(CLDAstream, PC client 등)·버전은 그대로" 를 명시한다.

## 데이터

```sql
create table public.cs_ticket_translations (
  ticket_id   uuid not null references public.cs_tickets(id) on delete cascade,
  lang        text not null check (lang in ('ko', 'en')),
  fields      jsonb not null,      -- { title, description, notes, status_note, timeline: [] }
  source_hash text not null,       -- 번역할 때 원문 칸들의 해시. 원문이 바뀌면 달라져 "오래된 번역" 판정
  translated_at timestamptz not null default now(),
  primary key (ticket_id, lang)
);
-- RLS: 다른 테이블과 같이 authenticated 만 select/insert/update/delete
```

- 한 CS 당 `ko`, `en` 두 행. 원문이 이미 그 언어면 그 칸은 원문을 그대로 넣는다 (Claude 가 판단).
- 월간 요약은 `cs_monthly_summaries` 에 영어용 칸(`content_en`, `issues_en`, `notes_en`)을 더한다. 요약 생성 때 Claude 가 `issues`·`notes` 를 한국어·영어 둘 다 돌려주게 하고(구조화 출력), 영어 마크다운은 `buildSummaryMarkdown` 을 영어 라벨로 다시 조립한다. 미해결 줄의 CS 제목은 `cs_ticket_translations` 의 `en` 을 쓰고, 없으면 원문 (내 결정). 영어 칸이 비어 있는 예전 요약은 영어 화면에서 "Regenerate to see in English" 안내.

## 번역 흐름

```
브라우저                                  Edge Function ai (mode=translate)
 ├ 저장 직후(등록·수정·빠른 저장·목록 심각도 X*) ──▶ ids: [저장한 CS id]
 └ 목록을 그릴 때, 보이는 CS 중
   현재 언어 번역이 없거나 source_hash 가
   원문과 다른 것 ─────────────────────────▶ ids: [...]  (한 번에 최대 N건, 나눠서)
                                            ├ cs_tickets 에서 원문 읽음 (요청자 JWT·RLS)
                                            ├ 원문 해시 계산 → 이미 최신이면 건너뜀
                                            ├ Claude: 칸별로 ko·en 둘 다 돌려받음 (구조화 출력)
                                            └ cs_ticket_translations upsert → 결과 반환
```

\* 심각도만 바뀐 저장은 번역할 칸이 안 바뀌므로 호출하지 않는다.

- **한 번 호출에 두 언어를 모두** 만든다. Claude 가 칸별로 `ko`·`en` 을 함께 돌려주고 두 행을 같이 upsert 한다 (원문이 이미 그 언어면 원문 그대로).
- **호출 조건 (내 결정)**: 화면 언어 쪽 번역이 없거나 오래됐을 때만 부른다. 단 한국어 화면에서는 번역 칸에 **한글이 하나도 없는** CS 만 부른다 (프론트의 간단한 한글 포함 검사). 한국어로 쓴 기록 때문에 한국어 사용자가 매번 번역을 일으키지 않게.
- **기존 기록 일괄 번역 (이번 범위에 포함)**: `ai` 에 `mode=translate_backfill` 을 둔다. 번역이 없거나 오래된 CS 를 오래된 순으로 묶어 처리하고, 다시 돌리면 남은 것만 한다. 그래야 영어 화면의 전체 기간 검색이 옛 기록도 영어로 찾는다. 이후 새 기록·수정은 위 흐름으로.
- **실행은 사이트의 「기존 기록 번역」 버튼** (사용자와 합의): 로그인한 사용자 권한으로 돌린다 (터미널에서 돌리면 별도 관리자 키가 필요해서). 진행 건수를 보여 주고, 남은 번역이 0건이면 버튼을 숨긴다. 위치는 빌더 결정 (예: 「CS 담당 관리」 창 아래, 또는 사이드바 하단).
- 번역이 오기 전에는 원문을 보여 주고, 도착하면 그 칸만 바꿔 그린다 (티켓 연동 `loadTickets` 와 같은 방식).
- 원문 해시는 브라우저와 Edge Function 이 같은 규칙으로 계산해야 한다 (번역 칸들을 정해진 순서로 이어 붙인 문자열의 SHA-256 등). 규칙은 lib 에 두고 양쪽 테스트로 고정.
- 번역 실패는 목록 위 오류 줄에 한 번 알리고(티켓 오류 줄과 같은 방식), 원문을 계속 보여 준다.

## 화면 영어화

- 사전 파일 `js/i18n.js` (ko·en). HTML 의 고정 글자는 `data-i18n` 속성으로 교체, JS 에서 만드는 글자는 `t('key')`.
- `lib.js` 의 `STATUS`, `SEVERITY`, `RECENCY` 라벨, 기기 표시 이름도 사전으로.
- 날짜: 시간대는 지금처럼 KST 고정. 요일·월 표기만 언어에 맞춤 (예: `2026-11-04 (Wed) 14:20`, 밀린 미해결 머리글 `Oct 2 · Sep 1`).
- `<html lang>` 을 화면 언어로.
- Edge Function 오류 문구: 영어 화면에서는 영어로 보여야 한다. 방법은 빌더 결정 (오류 코드 + 화면 사전, 또는 요청에 `lang` 을 넘겨 함수가 언어별 문구 반환).
- 슬랙 붙여넣기 결과 안내(검토 필요 문구)도 사전으로.
- **영어 화면에서도 기능은 같다** (사용자: "똑같은 사이트에 언어 설정"). 등록·수정·월간 요약 생성·CS 담당 관리 모두 된다. 슬랙 붙여넣기는 메시지 언어 그대로 칸을 채우고(번역하지 않음), 접수자 이름은 한글·영문 이름 모두 뽑도록 프롬프트를 고친다. `confidence_notes` 는 요청의 화면 언어로 (내 결정).
- 검색은 원문과 **현재 화면 언어의 번역**을 모두 대상으로 한다.
- CSV: 머리글·상태·심각도·기기는 화면 언어, 번역 칸은 화면 언어 쪽 (번역이 없으면 원문).

## 영문 가이드

- 지금 한국어 가이드(`docs/CS콘솔_사용가이드.html`, Artifact https://claude.ai/artifact/8BwYvzYg3qVAUaVoDAg217)와 같은 4부 구성·같은 화면 목록.
- 브라우저 언어를 영어로 둔 상태의 실제 화면을 **영어 예시 데이터**(고객사·사람 이름·제목·이력 모두 영어)로 캡처. 컴포넌트를 다시 그리지 않는다 (사용자 요구).
- 가이드 본문·범례도 영어. 글은 적게, 화면 예시는 많게 (한국어 가이드와 같은 원칙).
- 결과물: Artifact 와 단일 HTML 파일(`docs/CS-Console-Guide.html`) 둘 다.
- **한국어 원문 예시를 넣는다** (사용자 결정): 영어 예시 데이터 속에 한국어로 쓴 CS 2건 정도를 섞어, 영어 화면에서 "Translated from Korean · Show original" 이 보이는 장면과 원문(한글)으로 바꾼 장면을 함께 싣는다.
- 상단 「한국어 / English」 버튼도 한 장면.
- 스파이크(로컬 예시)에서 확인한 것: 영어 라벨이 길어 목록 CS 상태 칸에서 `Awaiting deploy` 가 잘리고, 상세의 `Ticket owner`·`Ticket status` 가 두 줄로 꺾인다. 칸 너비·라벨 길이를 영어 기준으로도 맞춘다 (한국어 화면은 그대로).

## 배포 순서

1. `supabase/schema.sql` 적용 (번역 테이블, 요약 영어 칸) — 사용자가 실행
2. Edge Function `ai` 재배포 — 사용자가 실행
3. 프론트 push (asset 버전 올림) — 사용자가 실행
4. 사이트에서 「기존 기록 번역」 한 번 실행. 그 전까지 영어 화면은 원문을 보여 주고, 연 달의 기록은 그때그때 번역된다

새 프론트가 번역 테이블이 없는 DB 를 만나도 화면은 원문으로 정상 동작해야 한다 (번역 조회 실패는 오류 줄 한 번).

## 빌더에게 맡기는 것

- Edge Function 오류 문구 영어화 방식
- 테스트 범위 (최소: 언어 판정, 사전 누락 키 검사, 해시 규칙, 번역 응답 정규화)
